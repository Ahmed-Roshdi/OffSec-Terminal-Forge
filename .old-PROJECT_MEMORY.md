# OffSec Terminal Forge - Codebase Architecture Document

## 1. Tracked Files and Their Exact Roles

Based on the latest codebase analysis (269 nodes, 460 edges), here are all tracked files and their inferred roles:

### Core Engine Modules (`engines/` directory)
- `engines/_fonts.py`: Font loading utility. Provides `load_fonts()` function used by alien_generator and dialogue_generator for text rendering.
- `engines/ai_engine.py`: AI Persona Engine — generates dialogue scenarios via Groq API and writes each one as a standalone script file to `output/scripts/`.
- `engines/alien_generator.py`: Fractal noise terrain engine — generates dot-matrix alien world maps. Creates procedural alien worlds for OffSec visual assets.
- `engines/core_engine.py`: Core Engine / The Compilor — applies cyberpunk glitch effects to base earth map images. Handles image transformation for map generation (RGB shift, scanlines, pixel sorting).
- `engines/dialogue_generator.py`: Render Engine — pure consumer of script files. Reads JSON scripts from `output/scripts/`, renders them as animated WebP HUD sequences over alien map backgrounds, writes to `output/dialogues/`.
- `engines/doc_updater.py`: Documentation Automation Engine — uses AI to generate README.md and DEVELOP.md files based on project architecture context stored in PROJECT_MEMORY.md.
- `engines/orchestrator.py`: Orchestrates the AI dialogue pipeline by running script generation and rendering in the same process to maintain pipeline timing consistency. Runs ai_engine.py followed by dialogue_generator.py.
- `assets/extract_captcha.py`: Utility for CAPTCHA image processing (likely used by dialogue generator for captcha frames).

## 2. CI/CD Pipeline Architecture

The project uses GitHub Actions for continuous integration and deployment, with a sophisticated workflow orchestration system managed by a "Master Workflow" that acts as a state controller.

### 2.1 Workflow Triggering Mechanisms

#### Master Workflow (State Controller)
- **File**: `.github/workflows/Master-Workflow.yml`
- **Triggers**: 
  - Scheduled: Runs 3x daily at 08:00, 16:00, 00:00 UTC (cron: `0 8,16,0 * * *`)
  - Manual: `workflow_dispatch` for testing or forced full runs
- **Function**: Acts as the "brain" of the system, analyzing asset counts and determining which subordinate workflows to trigger based on a balancing algorithm.

#### Workflow Dispatch Types
All workflows support `workflow_call` for being called by other workflows, and most also support `workflow_dispatch` for manual triggering.

### 2.2 Workflow Chain and Dependencies

The system maintains equilibrium among three primary asset types through a feedback loop:
1. **Maps** (`output/maps/alien_sector_*.webp`) - Generated by alien_generator.py
2. **Scripts** (`output/scripts/script_*.json`) - Generated by ai_engine.py  
3. **Dialogues** (`output/dialogues/dialogue_seq_*.webp`) - Generated by dialogue_generator.py
4. **Core Engine Maps** (`output/maps/glitched_map_*.webp`, `output/maps/latest_glitch.webp`) - Generated by core_engine.py (runs whenever base map asset exists)

#### Decision Logic in Master Workflow:
- **run_maps** = maps ≤ scripts (generate when maps are behind or equal to scripts)
- **run_ai** = scripts == 0 OR maps > scripts (generate scripts when none exist or maps have outpaced scripts)
- **run_dialogue** = dialogues == 0 OR scripts > dialogues (render dialogues when none exist or scripts have outpaced dialogues)
- **run_core** = base map asset exists (run core_engine.py whenever assets/map.png is present)

### 2.5 Artifact Flow and Steady State

The system maintains a dynamic equilibrium through the Master Workflow's decision logic:

1. **Maps vs Scripts Balance**: 
   - When maps ≤ scripts → Generate new maps
   - When maps > scripts → Generate new scripts (to catch up)

2. **Scripts vs Dialogues Balance**:
   - When scripts = 0 → Generate scripts (first run)
   - When scripts > dialogues → Render dialogues (to catch up)
   - When dialogues = 0 → Render dialogues (first run)

3. **Core Engine Independence**:
   - Runs whenever assets/map.png exists (independent of the main triplet balance)
   - Produces glitched versions of the base map for use in README/documentation

This creates a natural rotation where each cycle advances one or more stages, keeping the three main asset types (maps, scripts, dialogues) approximately balanced over time.

## 3. Engine Function Call Chains, Inputs, Outputs, and Dependencies

### 3.1 alien_generator.py
**Primary Purpose**: Generate procedural alien worlds and fractal noise maps for OffSec visual assets.

#### Key Functions:
- `generate_fractal_noise_map(width: int, height: int, seed: int) -> Image.Image`
  - **Purpose**: Creates base fractal noise terrain using multi-octave noise (Fractal Brownian Motion simulation)
  - **Inputs**: 
    - width (int): Image width in pixels
    - height (int): Image height in pixels
    - seed (int): Random seed for reproducible generation
  - **Output**: PIL Image object (grayscale "L" mode) representing fractal noise
  - **Dependencies**: Pure mathematical generation (random module only)
  - **Process**: 
    1. Generate multiple octaves of noise at different frequencies
    2. Blend octaves with decreasing weights (0.4, 0.2 for higher frequencies)
    3. Enhance contrast (1.8x) for definable terrain features

- `generate_alien_world(width: int = 1200, height: int = 800, save_to_disk: bool = True) -> tuple(Image.Image, str|None)`
  - **Purpose**: Main world generation function that creates a complete alien world visualization
  - **Inputs**:
    - width (int): Canvas width (default 1200px)
    - height (int): Canvas height (default 800px)
    - save_to_disk (bool): Whether to save output to file (default True)
  - **Output**: Tuple of (PIL Image object, output file path or None)
  - **Dependencies**: 
    - `generate_fractal_noise_map()` (for terrain base)
    - `_fonts.load_fonts()` (for text rendering)
    - `ImageEnhance.Contrast` (for terrain enhancement)
  - **Process**:
    1. Initialize canvas with dark space color (13, 17, 23 RGB)
    2. Generate fractal noise map for terrain elevation
    3. Determine sea/coast/highland/peak levels via randomized thresholds
    4. Draw elevation-colored dots in a grid pattern (every 12px)
    5. Add sector ID label and planet name using loaded fonts
    6. Optionally save to disk and update latest_map.webp symlink

- `generate_multiple_worlds(count: int = 1) -> list`
  - **Purpose**: Batch generation wrapper for multiple worlds
  - **Inputs**: count (int): Number of worlds to generate (default 1)
  - **Output**: List of generated image file paths
  - **Dependencies**: Repeatedly calls `generate_alien_world()`
  - **Process**: 
    1. Loop count times, calling generate_alien_world()
    2. Small delay (0.05s) between generations to avoid timestamp collisions
    3. Update latest_map.webp to point to most recent generation
    4. Return list of all generated file paths

#### Data Flow Summary:
```
Parameters (width, height, seed, count) 
    → generate_fractal_noise_map() 
    → generate_alien_world() 
        → _fonts.load_fonts() 
        → ImageDraw.Draw() for text/dots
        → ImageEnhance.Contrast() for terrain
    → Saved files: output/maps/alien_sector_{HEXID}.webp + output/maps/latest_map.webp
```

### 3.2 dialogue_generator.py
**Primary Purpose**: Render dialogue scripts as visual terminal-style images for OffSec assets (chat UI, avatars, speech bubbles, captcha frames). Pure consumer - reads scripts, produces visual output.

#### Key Functions:
- `_load_fonts() -> dict`
  - **Purpose**: Load multiple font sizes/styles for UI rendering
  - **Input**: sizes (dict): Mapping of font names to sizes (e.g., {"label": 22})
  - **Output**: Dictionary mapping font names to ImageFont.FreeTypeFont objects
  - **Dependencies**: 
    - Tries to load custom TTF from assets/fonts/
    - Falls back to PIL default font if custom font unavailable/missing

- `_text_size(draw: ImageDraw.ImageDraw, text: str, font) -> Tuple[int, int]`
  - **Purpose**: Calculate width/height of rendered text
  - **Inputs**: 
    - draw (ImageDraw): Drawing context
    - text (str): Text string to measure
    - font (ImageFont): Font object
  - **Output**: Tuple (width, height) in pixels
  - **Dependencies**: Uses built-in PIL text measurement (textbbox or textsize)

- `_apply_scanlines(image: Image.Image) -> Image.Image`
  - **Purpose**: Overlay horizontal scanline effect for retro monitor feel
  - **Input**: PIL Image (any mode)
  - **Output**: Image with scanline overlay (RGBA → RGB conversion)
  - **Process**: Draws semi-transparent black horizontal lines every 3px

- `_draw_avatar(draw: ImageDraw.ImageDraw, x: int, y: int, size: int, name: str, font) -> None`
  - **Purpose**: Draw circular avatar with user's initials and color-coded background
  - **Inputs**:
    - draw (ImageDraw): Drawing context
    - x, y (int): Top-left position
    - size (int): Avatar diameter in pixels
    - name (str): User/robot name for color/initials
    - font (ImageFont): Font for initials
  - **Dependencies**: 
    - `_color_for_name()` (deterministic color from name hash)
    - `_initials()` (extract initials from name)
    - `_text_size()` (to center initials)
  - **Process**:
    1. Generate avatar background color from name hash
    2. Draw filled circle (ellipse) with that color
    3. Calculate and draw white initials centered in circle

- `_draw_bubble(draw: ImageDraw.ImageDraw, text: str, x: int, y: int, align: str, fonts: dict, user_name: str, decal: str) -> None`
  - **Purpose**: Render speech bubble with text, optionally attaching to an avatar
  - **Inputs**:
    - draw (ImageDraw): Drawing context
    - text (str): Dialogue text to display
    - x, y (int): Base position for bubble
    - align (str): "left" or "right" (determines avatar/bubble positioning)
    - fonts (dict): Font objects from _load_fonts()
    - user_name (str): Speaker name (for avatar/color)
    - decal (str): Small identifier text in bubble corner
  - **Dependencies**: 
    - `_text_size()` (for text wrapping and sizing)
    - `_draw_avatar()` (if align creates space for avatar)
  - **Process**:
    1. Word-wrap text to BUBBLE_WRAP (48 chars)
    2. Calculate bubble dimensions based on text lines
    3. Determine colors/positions based on alignment (left = cyan theme, right = magenta theme)
    4. Draw avatar if space allocated
    5. Draw speech bubble polygon with border and inner line
    6. Draw speaker name and decal text
    7. Draw wrapped dialogue lines

- `_build_chat_frame(visible: List[Dict], fonts: dict, width: int, height: int) -> Image.Image`
  - **Purpose**: Assemble a full chat frame from multiple dialogue elements
  - **Inputs**:
    - visible (List[Dict]): List of message dictionaries to display
    - fonts (dict): Font objects from _load_fonts()
    - width, height (int): Canvas dimensions
  - **Output**: Composite PIL Image of chat UI
  - **Dependencies**: `_draw_bubble()` (called once per visible message)
  - **Process**: 
    1. Create base canvas with BG_COLOR (9, 10, 15)
    2. For each message in visible list:
       - Calculate x-position based on alignment (left=80, right=width-80)
       - Draw bubble with message text
       - Increment y-position by message height + padding
    3. Apply scanlines overlay via `_apply_scanlines()`
    4. Return final composed frame

- `_build_captcha_frame(fonts: dict, width: int, height: int) -> Image.Image`
  - **Purpose**: Generate a CAPTCHA-like challenge image for final frame
  - **Inputs**:
    - fonts (dict): Font objects from _load_fonts()
    - width, height (int): Canvas dimensions
  - **Output**: CAPTCHA PIL Image with scanlines
  - **Dependencies**: `_apply_scanlines()`
  - **Process**:
    1. Create base canvas with BG_COLOR
    2. If assets/captcha.png exists: load, resize (max width 520px), center and paste
    3. Else: Draw "MISSING: assets/captcha.png" error text in red
    4. Apply scanlines overlay

- `_load_background_map() -> Optional[Image.Image]`
  - **Purpose**: Load most recently generated alien map for background, or generate fallback
  - **Input**: None
  - **Output**: PIL Image object sized to CANVAS_W x CANVAS_H, or None if error
  - **Dependencies**: 
    - `glob.glob()` to find alien_sector_*.webp files
    - `os.path.getmtime()` to find most recent
    - `alien_generator.generate_alien_world(save_to_disk=False)` for fallback
  - **Process**:
    1. Find all alien_sector_*.webp files in output/maps/
    2. Sort by modification time (newest first)
    3. If found: load and resize to fit canvas while preserving aspect ratio
    4. If not found: Generate temporary alien world in memory (not saved to disk)
    5. Center image on canvas of BG_COLOR, preserving aspect ratio

- `_load_script(filepath: str) -> Optional[List[Dict]]`
  - **Purpose**: Load and validate a script JSON file from output/scripts/
  - **Input**: filepath (str): Full path to script JSON file
  - **Output**: List of dialogue dictionaries, or None if invalid
  - **Dependencies**: json module
  - **Process**:
    1. Load and parse JSON file
    2. Extract "script" key value
    3. Validate it's a non-empty list
    4. Return script list or None on failure/error

- `generate_dialogue_from_script(script: List[Dict], basename: str, bg_image: Optional[Image.Image] = None) -> str`
  - **Purpose**: Main processing pipeline: loads script data, builds frames, saves images
  - **Inputs**:
    - script (List[Dict]): Dialogue script from JSON file
    - basename (str): Base name for output files
    - bg_image (Optional[Image.Image]): Pre-loaded background (defaults to internal load)
  - **Output**: String path to generated WebP file
  - **Dependencies**: 
    - `_load_fonts()`, `_load_background_map()` (if bg_image not provided)
    - `_build_chat_frame()`, `_build_captcha_frame()`
    - Global constants for frame durations and canvas size
  - **Process**:
    1. Load fonts for text rendering
    2. Load background image (use provided or load internal)
    3. Pre-process script: add default decals, calculate bubble heights
    4. Build frames using sliding window algorithm:
       - Start with background frame (longer duration = FRAME_DURATION_BG)
       - For each dialogue line: 
         * Add to visible set
         * Remove oldest lines if canvas would overflow vertically
         * Build chat frame from visible set (duration: FRAME_DURATION_CHAT)
       - End with captcha frame (duration: FRAME_DURATION_FINAL)
    5. Save as animated WebP with lossless quality
    6. Copy to fixed location LATEST_PATH (output/dialogues/latest_dialogue.webp)
    7. Return output file path

- `main() -> None`
  - **Purpose**: Entry point for dialogue generation workflow
  - **Input**: None (uses environment variables and file discovery)
  - **Output**: Side effects: creates/updates files in output/dialogues/
  - **Dependencies**: 
    - `_load_background_map()`
    - `_load_script()` 
    - `generate_dialogue_from_script()`
  - **Process**:
    1. Ensure output/dialogues/ and output/scripts/ directories exist
    2. Load background map (_load_background_map)
    3. Select script to render (priority: 
       - Matching PIPELINE_RUN_TS env var
       - Most recent script_*.json
       - Built-in FALLBACK_DIALOGUES if no scripts found)
    4. Generate dialogue from selected script
    5. Log results (file path and size)

#### Data Flow Summary:
```
Script JSON files (output/scripts/script_*.json) 
    OR FALLBACK_DIALOGUES
    → _load_script() / direct fallback use
    → _load_fonts() 
    → [_load_background_map() OR alien_generator.generate_alien_world()]
    → generate_dialogue_from_script() 
        → _build_chat_frame() ← [_draw_bubble() ← [_draw_avatar(), _text_size()]]
        → _build_captcha_frame() ← [_apply_scanlines()]
    → Animated WebP saved to: 
        output/dialogues/dialogue_seq_{basename}.webp
        output/dialogues/latest_dialogue.webp (copy)
```

### 3.3 core_engine.py
**Primary Purpose**: Apply cyberpunk/offsec glitch effects to base earth map images (e.g., for alien world maps or UI backgrounds).

#### Key Functions:
- `load_base_image(image_path: str) -> Image.Image`
  - **Purpose**: Load and convert base map image to RGBA
  - **Input**: image_path (str): File path to base image (defaults to "assets/map.png")
  - **Output**: PIL Image object in RGBA mode
  - **Dependencies**: File system access, PIL Image.open()
  - **Process**:
    1. Verify file exists at image_path
    2. Open image with PIL
    3. Convert to RGBA (ensuring alpha channel)
    4. Log loaded image info (path and dimensions)
    5. Return RGBA Image object

- `apply_rgb_shift(image: Image.Image, shift: int = 10) -> Image.Image`
  - **Purpose**: Create chromatic aberration effect (red/blue channel displacement)
  - **Inputs**:
    - image (Image.Image): Input image in RGBA mode
    - shift (int): Pixel displacement amount (default 10, typical range 5-15)
  - **Output**: Image with shifted red/blue channels (green unchanged)
  - **Dependencies**: PIL Image.split() and Image.merge()
  - **Process**:
    1. Split image into R, G, B, A channels
    2. Create blank canvases for red and blue channels
    3. Paste red channel shifted RIGHT by shift pixels
    4. Paste blue channel shifted LEFT by shift pixels
    5. Merge shifted R, original G, shifted B, original A channels
    6. Return recombined RGBA image

- `apply_scanlines(image: Image.Image, line_spacing: int = 4, line_brightness: float = 0.2) -> Image.Image`
  - **Purpose**: Overlay monitor scanline effect
  - **Inputs**:
    - image (Image.Image): Input image
    - line_spacing (int): Pixel distance between scanlines (default 4, typical 3-6)
    - line_brightness (float): Scanline brightness as fraction 0-1 (default 0.2)
  - **Output**: Image with semi-transparent black horizontal lines
  - **Dependencies**: ImageDraw.Draw()
  - **Process**:
    1. Create transparent overlay same size as image
    2. For each y coordinate at line_spacing intervals:
       - Draw 1-pixel black line from (0,y) to (width,y)
       - Line opacity = line_brightness * 255
    3. Composite overlay onto image using alpha_blending
    4. Return result as RGBA → RGB converted image

- `apply_pixel_sort(image: Image.Image, mask_threshold: int = 128, sort_by: str = "hue") -> Image.Image`
  - **Purpose**: Sort pixels in each row by hue/saturation/value for "datamosh" effect
  - **Inputs**:
    - image (Image.Image): Input image
    - mask_threshold (int): Brightness threshold 0-255 (default 128)
    - sort_by (str): Sort key - "hue", "saturation", or "value" (default "hue")
  - **Output**: Image with rows of pixels sorted horizontally
  - **Dependencies**: PIL pixel access via load(), basic arithmetic for HSV conversion
  - **Process**:
    1. Convert image to HSV-like space for sorting calculations
    2. For each row (y coordinate):
       - Identify pixels where brightness > mask_threshold
       - For qualifying pixels, calculate HSV tuple:
         * Hue: 0-360° based on RGB ratios
         * Saturation: 0-1 (delta/max if max>0 else 0)
         * Value: 0-1 (max/255)
       - Sort qualifying pixels by selected HSV component
       - Rewrite sorted pixel values back to original positions
    3. Return image with sorted rows (unsorted pixels unchanged)

- `apply_glitch_effects(image: Image.Image) -> Image.Image`
  - **Purpose**: Apply all three glitch effects in sequence with randomized parameters
  - **Input**: PIL Image (typically base map)
  - **Output**: Fully glitched PIL Image
  - **Dependencies**: 
    - `apply_rgb_shift()` (shift: random 5-15)
    - `apply_scanlines()` (spacing: random 3-6, brightness: random 0.1-0.4)
    - `apply_pixel_sort()` (threshold: random 100-200, method: random choice)
  - **Process**:
    1. Generate random parameters for each effect within specified ranges
    2. Apply effects in sequence: RGB shift → Scanlines → Pixel sort
    3. Log applied parameters for debugging/transparency
    4. Return final composed image

- `main() -> None`
  - **Purpose**: Entry point for map processing workflow
  - **Input**: None (uses hardcoded/default paths)
  - **Output**: Side effects: creates/updates files in output/maps/
  - **Dependencies**:
    - `load_base_image()` (fixed path: assets/map.png)
    - `apply_glitch_effects()`
    - Standard library: os, time, shutil
  - **Process**:
    1. Ensure output/maps/ directory exists
    2. Load base map from assets/map.png (fail with helpful message if missing)
    3. Apply glitch effects with random parameters
    4. Generate timestamp: ts = int(time.time())
    5. Save timestamped copy: output/maps/glitched_map_{ts}.webp
    6. Copy/overwrite latest version: output/maps/latest_glitch.webp
    7. Log save operations to console

#### Data Flow Summary:
```
Base Map: assets/map.png
    → load_base_image() 
    → apply_glitch_effects()
        → apply_rgb_shift(shift=random 5-15)
        → apply_scanlines(spacing=random 3-6, brightness=random 0.1-0.4)
        → apply_pixel_sort(threshold=random 100-200, method=random choice)
    → Saved files:
        output/maps/glitched_map_{timestamp}.webp
        output/maps/latest_glitch.webp (copy)
```

### 3.4 ai_engine.py
**Primary Purpose**: AI Persona Engine — generates dialogue scenarios via Groq API and writes each one as a standalone script file to output/scripts/.

#### Key Functions:
- `_robot_name() -> str`
  - **Purpose**: Generate random robot/unit names for dialogue
  - **Input**: None
  - **Output**: String robot name (e.g., "UNIT-7A", "AURORA-42")
  - **Dependencies**: random module
  - **Process**:
    1. 40% chance: PREFIX-NUMBER format (e.g., "UNIT-7A")
    2. 60% chance: FANCY-NUMBER format (e.g., "AURORA-42")
    3. Select random components from predefined lists
    4. Ensure uniqueness when generating pairs

- `generate_robot_pair() -> List[str]`
  - **Purpose**: Generate two distinct robot names for dialogue
  - **Input**: None
  - **Output**: List of two unique robot names [name_a, name_b]
  - **Dependencies**: `_robot_name()`
  - **Process**:
    1. Generate first name
    2. Generate second name, repeat if identical to first
    3. Return pair

- `build_prompt(robot_pair: List[str], min_lines: int, max_lines: int) -> str`
  - **Purpose**: Construct prompt for Groq API to generate dialogue script
  - **Inputs**:
    - robot_pair (List[str]): Two robot names [left_aligned, right_aligned]
    - min_lines (int): Minimum dialogue lines to generate
    - max_lines (int): Maximum dialogue lines to generate
  - **Output**: Formatted prompt string for AI model
  - **Dependencies**: String formatting only
  - **Process**:
    1. Create JSON-structured instruction requiring specific output format
    2. Specify required robot names and alignment (left/right)
    3. Define line count bounds (min_lines to max_lines)
    4. Specify tone: OffSec jargon, sarcasm, dark humor, tech references
    5. Constrain text length: max 18 words per line
    6. Demand pure JSON output (no prose/markdown)

- `_call_groq(prompt: str, api_key: str) -> Optional[str]`
  - **Purpose**: Make HTTP request to Groq API with retry logic
  - **Inputs**:
    - prompt (str): Formatted request for AI model
    - api_key (str): Groq API authentication token
  - **Output**: Raw string response from API, or None on failure
  - **Dependencies**: requests module, time for backoff
  - **Process**:
    1. Prepare headers with Authorization bearer token
    2. Prepare JSON payload with model and parameters
    3. For attempt in 1..MAX_RETRIES (3):
       - Send POST request to Groq API endpoint
       - On HTTP 401/403: Log auth error, return None (don't retry)
       - On HTTP 429: Log rate limit, exponential backoff (2^attempt seconds)
       - On other errors: Log, exponential backoff
       - On timeout: Log, exponential backoff
       - On success: Return response content
    4. If all attempts fail: Log exhaustion, return None

- `_extract_json(text: str) -> Dict`
  - **Purpose**: Extract JSON object from potentially wrapped model response
  - **Input**: text (str): Raw model response (may contain markdown/prose)
  - **Output**: Dictionary parsed from JSON, or raises ValueError
  - **Dependencies**: json module
  - **Process**:
    1. Strip whitespace
    2. Try direct JSON parsing
    3. If fails, find first '{' and last '+' 
    4. Extract substring and try parsing again
    5. If both fail: raise ValueError("No valid JSON object found")

- `_save_script(obj: Dict, path: str) -> None`
  - **Purpose**: Save script object as JSON file to disk
  - **Inputs**:
    - obj (Dict): Script dictionary to save
    - path (str): Full file path for output
  - **Output**: None (file written to disk)
  - **Dependencies**: json module
  - **Process**:
    1. Open file at path for writing (UTF-8)
    2. Dump obj as JSON with indentation=2, ensure_ascii=False
    3. Close file

- `generate_scenarios(request_context: str = "") -> List[str]`
  - **Purpose**: Generate SCENARIOS_PER_RUN dialogue scripts and save to files
  - **Input**: request_context (str): Optional theme/context to include in prompt
  - **Output**: List of created file paths
  - **Dependencies**: 
    - `_looks_like_valid_key()` (diagnostic only)
    - `generate_robot_pair()`
    - `build_prompt()`
    - `_call_groq()`
    - `_extract_json()`
    - `_local_fallback()` (for when Groq unavailable)
    - `_save_script()`
    - uuid, time, os modules
  - **Process**:
    1. Get/set PIPELINE_RUN_TS environment variable for tracking
    2. Check Groq API key availability (diagnostic only - doesn't block)
    3. For i in 1..SCENARIOS_PER_RUN:
       - Generate unique robot pair
       - Attempt Groq API call with built prompt
       - If Groq fails/unavailable: use local fallback dialogue
       - Construct filename: script_{TS}_{i:02d}_{UUID8}.json
       - Save script object to output/scripts/filename
       - Record filepath in results list
    4. Return list of created file paths

- `main() -> None`
  - **Purpose**: Command-line entry point for AI script generation
  - **Input**: Optional --request/-r argument for additional context
  - **Output**: Side effects: creates files in output/scripts/
  - **Dependencies**: argparse module
  - **Process**:
    1. Parse command line arguments (--request/-r)
    2. Call generate_scenarios() with provided request context
    3. Log completion: number of script files created

#### Data Flow Summary:
```
Environment: PIPELINE_RUN_TS (optional) + GROQ_API_KEY (optional)
    → generate_scenarios()
        → generate_robot_pair() × scenarios_per_run
        → build_prompt() 
        → [_call_groq(Groq API) OR _local_fallback()]
        → _extract_json() → _save_script()
    → Output files: 
        output/scripts/script_{TIMESTAMP}_{INDEX}_{UUID8}.json
```

### 3.5 orchestrator.py
**Primary Purpose**: Orchestrates the AI dialogue pipeline by running script generation and rendering in the same process to maintain pipeline timing consistency.

#### Key Functions:
- `run_ai_engine() -> bool`
  - **Purpose**: Execute ai_engine.py as subprocess with proper environment
  - **Input**: None
  - **Output**: Boolean success status
  - **Dependencies**: 
    - subprocess module
    - os, sys modules
    - datetime, timezone for timestamp generation
  - **Process**:
    1. Copy current environment
    2. Ensure PIPELINE_RUN_TS is set (generate if missing: YYYYMMDDTHHMMSSZ format)
    3. Run [sys.executable, "ai_engine.py"] with:
       - Custom environment (including PIPELINE_RUN_TS)
       - Working directory set to script's directory
       - 60-second timeout
       - Capture stdout/stderr
    4. Log stdout, log stderr as warning if present
    5. Return True if returncode==0, False otherwise
    6. On timeout or exception: Log error, return False

- `run_dialogue_generator() -> bool`
  - **Purpose**: Execute dialogue_generator.py as subprocess with shared environment
  - **Input**: None
  - **Output**: Boolean success status
  - **Dependencies**: Same as run_ai_engine()
  - **Process**:
    1. Use same environment as ai_engine.py (including PIPELINE_RUN_TS)
    2. Run [sys.executable, "dialogue_generator.py"] with:
       - Same custom environment
       - Same working directory
       - 60-second timeout
       - Capture stdout/stderr
    3. Log stdout, log stderr as warning if present
    4. Return True if returncode==0, False otherwise
    5. On timeout or exception: Log error, return False

- `main() -> None`
  - **Purpose**: Entry point for orchestration workflow
  - **Input**: None
  - **Output**: Side effects: runs ai_engine.py then dialogue_generator.py sequentially
  - **Dependencies**: 
    - run_ai_engine()
    - run_dialogue_generator()
    - sys module for exit codes
  - **Process**:
    1. Log start of orchestration
    2. Run ai_engine.py via run_ai_engine()
       - If fails: log abort, exit(1)
    3. Run dialogue_generator.py via run_dialogue_generator()
       - If fails: log abort, exit(1)
    4. Log successful completion of both stages

#### Data Flow Summary:
```
Environment Inheritance + PIPELINE_RUN_TS Management
    → run_ai_engine()
        → subprocess: python engines/ai_engine.py
        → Creates: output/scripts/script_{TIMESTAMP}_{INDEX}_{UUID8}.json
    → run_dialogue_generator() 
        → subprocess: python engines/dialogue_generator.py
        → Input: output/scripts/script_*.json (selection logic inside)
        → Creates: output/dialogues/dialogue_seq_{basename}.webp + output/dialogues/latest_dialogue.webp
```

### 3.6 _fonts.py
**Primary Purpose**: Font loading utility for text rendering in alien_generator and dialogue_generator.

#### Key Functions:
- `load_fonts(sizes: dict) -> dict`
  - **Purpose**: Load font files at specified sizes, with fallback to default
  - **Input**: sizes (dict): Mapping {font_name: size_in_pixels}
  - **Output**: Dictionary {font_name: ImageFont object}
  - **Dependencies**: 
    - os.path.exists() for font directory check
    - PIL.ImageFont.truetype() and .load_default()
  - **Process**:
    1. Set BASE_DIR to project root (parent of parent of this file)
    2. Set FONTS_DIR to BASE_DIR/assets/fonts
    3. Auto-detect first .ttf file in FONTS_DIR (if any exist)
    4. For each name,size in sizes dict:
       - If font_path found: try loading truetype font at size
       - On failure: print warning, fallback to default
       - If no font_path found: use default PIL font
    5. Return dictionary of loaded/named fonts

### 5.3 Steady State Behavior
Over multiple workflow executions, the system converges toward equilibrium where:
- Maps ≈ Scripts ≈ Dialogues (within ±1)
- Core Engine runs independently whenever assets/map.png is present
- Each pipeline execution advances the system toward balance
- No permanent backlog accumulates in any asset type

This creates a self-regulating continuous generation system that maintains a steady flow of fresh assets while preventing runaway accumulation of any single type.
